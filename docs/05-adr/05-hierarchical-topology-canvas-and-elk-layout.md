# ADR-05: 分层复合架构拓扑画布选型、去 Agent 物理建模与一致性比对融合

- **文档编号**：`05-hierarchical-topology-canvas-and-elk-layout.md`
- **日期**：2026-10-31
- **状态**：已采纳 (Accepted)
- **关联特性**：`F-04`（静态架构拓扑视图）、`F-05`（实测调用拓扑还原与架构一致性验证）

---

## 1. 背景与问题陈述 (Context & Problem Statement)

在原有设计中，架构工作台存在若干交互与建模局限：
1. **局部孤岛视野**：前端拓扑仅支持按单个子系统查看（传 `subsystem_id`），无法展示全系统级宏观依赖，跨子系统的核心调用关系被物理割裂；
2. **平铺扁平化失真**：系统、功能组、模块在原有画布中被降维平铺为同级圆点，无法体现架构设计的「包含（Containment）与边界」语义；
3. **交互能力缺失**：固定尺寸 SVG 无法平移、缩放、按层级折叠展开或拖拽，随着服务模块增多，连线交叉严重失控；
4. **物理视图概念混淆**：此前物理视图将 `Agent` 节点作为拓扑容器，导致用户混淆了“数据面无状态探测器”与“业务物理部署边界”；
5. **一致性验证孤立**：实测流量比对结果位于独立页签，脱离了直观的架构拓扑图，用户无法一眼感知哪条架构边发生了漂移越权。

---

## 2. 决策方案 (Decisions)

### 决策 1：采用 React Flow (`@xyflow/react`) + ELK.js 作为分层复合图核心引擎
- **选型结论**：选用 React Flow v12 承载 DOM 视口交互（平移、缩放、多选、小地图），结合 `elkjs/lib/elk-worker` 在独立的 Web Worker 中运行分层复合图布局（Layered Compound Graph）。
- **决策依据**：
  1. ELK 是开源领域对多级嵌套容器（`elk.hierarchyHandling: "INCLUDE_CHILDREN"`）和正交连线（Orthogonal Routing）支持最完备的算法库，天生契合架构蓝图质感；
  2. React Flow 基于标准 React 组件渲染节点，能够 100% 严谨继承工作区 Vanilla CSS 与 `--color-*` Design Tokens，确保暗黑与亮色主题完美无缝切换；
  3. 布局计算跑在 Worker 线程，彻底解放 UI 主线程，防止大图重新排版时导致页面掉帧。

### 决策 2：全系统单画布 + 纯前端动态边汇总 (Client-side Edge Rollup)
- **选型结论**：后端仅返回全量层级树与不可分割的原子叶子依赖边（模块到模块）；前端根据各容器节点的当前折叠/展开状态，通过纯函数实时将叶子边向上卷聚（Rollup）到最近的可见祖先节点上。
- **决策依据**：展开与折叠是用户高频交互，若每次层级切换均向后端发起网络请求，不仅增加后端压力，更会导致交互卡顿，破坏“连续逐层探索”的用户体验。全系统叶子依赖数据量在经过 Gzip 后仅数百 KB，一次性加载至前端完全满足性能预算。

### 决策 3：显式展开为主（双击 + 滑杆），语义缩放作为可选开关；手动排版不持久化
- **选型结论**：
  1. 画布展开/折叠主交互为：**双击容器节点**，或滑动顶部工具栏的 **层级滑杆 (`L0 子系统/进程组` ~ `Ln 模块`)**；
  2. 基于视口像素占比的滚轮自动展开（语义缩放）设计为工具栏中的可选开关，**默认保持关闭**，避免用户在单纯缩放全图时引发意外的局部重新排版与视觉跳跃；
  3. 用户在画布上手动拖动节点仅作为临时会话排版，**不保存至后端与 localStorage**，提供“重置布局”按钮可随时恢复 ELK 最优布局。

### 决策 4：物理部署视图去 Agent 化，模型收敛为「进程组 (`ProcessGroup`) → 进程 (`Process`)」
- **选型结论**：彻底从架构拓扑图中剥离 `Agent` 节点。物理部署视图的层级结构严格规范为：  
  $$\text{System} \to \text{进程组 (ProcessGroup)} \to \text{物理进程 (Process)} \to \text{承载模块 (Module)}$$
- **决策依据**：`Agent` 的本质是安装在主机上的轻量守护进程、eBPF 字节流采集器和 Mock 注入执行器，属于平台底层数据面探测器，而非业务部署架构的固有组成部分。物理视图应当反映的是微服务集群（进程组）与网络端点（`AdvertiseIP:ListenPort`）的拓扑关系。

### 决策 5：将「架构一致性验证」合并为拓扑画布的动态叠加层 (Consistency Overlay)
- **选型结论**：废除独立的“架构一致性比对”隔离页签。在静态拓扑画布顶部提供录制批次选择器，一键激活一致性比对模式。
- **决策依据**：六分类结果（`VERIFIED`、`VIOLATION`、`UNCOVERED`、`NOT_MONITORED`、`NOT_OBSERVABLE`、`UNATTRIBUTED`）直接在当前可见的架构边上按最差状态着色，并允许点击边直接调出四段报文解剖抽屉（`PacketAnatomyDrawer`），实现了“设计态架构”与“运行态实测流量”在同一画布上的无缝统一。

## 3. 后果与影响 (Consequences)

### 正向收益 (Positive)
1. **全局架构全景可控**：支持从最高级子系统/进程组依赖一览全局，亦可逐层下钻至具体模块接口细节；
2. **语义更纯粹**：去 Agent 化让物理拓扑回归业务网络本质，架构师与运维人员直面真实进程与端口；
3. **闭环体验提升**：一致性比对直接在架构图上高亮漂移边，架构违规调用无所遁形。

### 潜在代价与应对 (Trade-offs & Mitigations)
1. **依赖包体积增加**：引入 `@xyflow/react` 与 `elkjs` 会增加前端构建体积（约 1.5MB）。  
   *应对*：通过 Vite 动态 `React.lazy()` 与独立 Chunk 拆分，仅在用户访问 `/architecture` 拓扑工作台时按需异步加载。
2. **嵌套图布局复杂度**：深层嵌套容器在 ELK 计算时耗时高于扁平图。  
   *应对*：限制默认展开深度为最高层（L0），通过 Web Worker 异步计算并配合锚点平滑过渡动画，确保 300 节点内排版时间控制在 200ms 以内。
