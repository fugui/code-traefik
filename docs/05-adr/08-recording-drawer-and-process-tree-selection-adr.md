# ADR-08: 协同录制抽屉重构与进程树选择器设计 (Recording Drawer & Process Tree Selection)

## 1. 状态 (Status)
**已采纳 (Accepted)** - 2026-11-01

## 2. 背景与问题定义 (Context & Problem Statement)
在流量录制工作台（`RecordingWorkbenchPage`）中，用户点击「发起协同录制」时，原界面采用居中模态对话框（`Modal width="lg"`），在实际研发展开与可用性评审中暴露出以下三项严重痛点：

1. **上部空间拥挤与视觉压迫**：
   - 「素材归属作用域」单选配置采用包含冗长说明的原生单选框（`个人私有调试素材 (PRIVATE - 仅本人可见与可调试)` 与 `团队公共基线素材 (SHARED - 供团队全员重放回归)`），横向排布几乎占满整行，字距紧凑，与上方的批次名称输入框缺少留白与层次感。
   - 居中 Modal 顶部遮罩的提示文字（如“点击背景区域关闭”）容易与弹窗标题重叠，带来视觉污染。
2. **缺乏宿主 Agent 维度选择与状态防呆**：
   - 流量录制底层是以 **Agent 为物理宿主单位下发 eBPF 探针排他租约（Lease）**。
   - 原界面完全隐藏了 Agent 选择，仅在每个进程末尾以次级徽章渲染 `Agent: xxx`。当宿主机处于 `OFFLINE`（离线）或已有活跃租约（被其他成员占用）时，用户无法提前感知，直接勾选进程提交后才触发后端 `400 Bad Request` 报错。
3. **下部进程平铺混乱，缺乏微服务拓扑进程树**：
   - 原组件采用简陋的平铺无序列表（`code-process-selector-box`），每个选项塞入复选框、进程名、端口、组名徽章、Agent 徽章；在容器宽度受限时，文字强制折行，产生例如 `(端[ ]：9002)` 的严重排版撕裂与重叠。
   - 分布式场景中服务进程众多，用户无法按**业务进程组**快速识别调用链路关系，更无法支持「组级一键全选 / 反选」与快捷过滤。
4. **居中对话框垂直延展力受限**：
   - Modal 垂直高度有限，内容增多时产生局促的内部滚动条，确认与取消按钮被推到视口底部，无法实现实时已选进程计数与常驻操作。

## 3. 架构决策 (Architectural Decisions)

### 3.1 容器形态演进：全面迁移至右侧抽屉 (`Drawer`)
- 废弃居中 `Modal`，全面迁移至 `@code/common` 统一的 `Drawer` 组件（宽度设为 `680px`），贯穿视口全高（`100vh`）。
- **Sticky 吸底 Footer**：操作栏常驻屏幕右下角，左侧动态展示汇总摘要（如 `已选 N 个业务进程 · 属于 <AgentName>`），右侧固定「取消」与「立即启动录制」按钮，彻底解决表单滚动导致操作按钮移位的问题。

### 3.2 表单上层解挤：卡片式作用域单选器 (Scope Radio Cards)
- 废除原生密排单选框，改为并排的两列卡片选择组件：
  - **PRIVATE 卡片**：标题「个人私有调试素材」，附带 `PRIVATE` 语义徽章，次级文本说明「仅本人可见与调试，用后可随时清理，不污染基线」；
  - **SHARED 卡片**（管理员可用）：标题「团队公共基线素材」，附带 `SHARED` 品牌徽章，次级文本说明「全员可见，可作为架构一致性比对与自动化回归基线」。
- 采用 `var(--color-bg-surface)`、`var(--color-border-primary)` 与选中态高亮边框，大幅提升界面呼吸感与现代质感。

### 3.3 单 Agent 架构下的运行环境选择器 (Agent Selection & Guard)
基于研发环境（单台主机承载多微服务进程，一个 Agent 通过 eBPF 内核挂载即可同时录制其上多个进程通信）的实际情况，采用「顶部 Agent 运行环境选择栏 + 下方纯业务进程树」架构：
- 顶部提供 **「目标宿主机 Agent」** 下拉选择器，选项展示 `🖥️ <AgentName> (<IP>) [🟢 在线/空闲]`。
- **自动化零点击（Zero-Click Default）**：抽屉打开时，系统自动识别并默认选中首个在线且未被占用的 Agent。
- **状态防呆门禁**：若选中的 Agent 处于离线（`OFFLINE`）或被他人录制占用（`lease_type != ""`），下方进程树自动只读禁用，并在选择器下方即时渲染警告提示横幅，提前拦截非法提交。

### 3.4 纯业务进程树 (Business Process Hierarchy Tree)
以当前选定 Agent 下的业务进程组（`GroupName`）为聚合根，构建树形选择器：
```text
▼ [✓] 核心业务组 (1/1)
    └── [✓] sut-order                   [端口: 9001] [模块: 订单结算]
▼ [✓] 支撑服务组 (2/2)
    ├── [✓] backend-account             [端口: 9002] [模块: 账户资金]
    └── [✓] backend-inventory           [端口: 9003] [模块: 库存中心]
▼ [ ] 客户端/网关 (0/1)
    └── [ ] CLI                         [纯客户端]
```
- **组级全选 / 半选联动**：
  - 点击组复选框一键勾选/反选该组全部进程；
  - 组内部分进程勾选时，组复选框自动呈现半选（`indeterminate`）状态；
  - 组标题右侧展示 `(已选/总数)` 统计（如 `2/2`、`0/1`）。
- **进程项整洁排版**：
  - 复选框 + 进程名加粗 + 端口 Badge（如 `9001` 浅蓝徽章，`0` 端口显示为灰色 `纯客户端` 徽章）；
  - 次级属性单行排布，禁止换行破坏栅格；
- **关键字快速过滤**：
  - 树顶端配备过滤搜索框，实时按进程名、端口、组名过滤节点，过滤时自动保持命中节点的父组展开；
  - 提供快捷「全选可用」与「清空选择」按钮。

## 4. 实施后果与收益 (Consequences)
- **正面收益 (Positive)**：
  - 彻底消除了表单上部拥挤、长文本单选折叠拥挤的视觉缺陷；
  - 用户对录制下发的物理机器（Agent）与网络状态拥有 100% 明确预期与防呆保护；
  - 业务进程以树形清晰呈现，支持整组批量勾选，极大降低操作负荷；
  - 100% 遵循 `theme.css` 语义 Token，亮色/暗色模式均具备高端质感。
- **兼容性 (Compatibility)**：
  - 对外依然向 `/api/recording-sessions` 提交 `target_process_ids`，后端 API 契约保持完全兼容。
